Project Status

Use case

A small client side error reporter. Include it in your website and every uncaught error and unhandled promise rejection in your visitors' browsers is sent to your server, together with details about the browser, the operating system and the page. You learn about problems in production without asking users to open their developer tools.

Features included:

  • Registers itself on load, no further code needed.
  • Reports each distinct error only once per page view.
  • Detailed browser, engine, operating system and device information via the optional ua-parser-js.
  • Filters for known noise and unsupported browsers, extendable with your own rules.
  • Hooks for successful, failed and ignored reports.

Content

Installation

Install it via a package manager and import it once in your entry module:

npm install errorreporter

import 'errorreporter'

Or include the self-contained bundle "dist/bundle/index.js" as early as possible in your HTML, ideally as first script. It contains all needed polyfills, has no dependencies, runs synchronously as a plain (non module) script in any environment and is then available as global "errorreporter":

<script src="https://unpkg.com/errorreporter@latest/dist/bundle/index.js"></script>

For browser details load ua-parser-js before, so that a global "UAParser" exists when the error reporter is loaded. Without it reports contain the raw user agent only and browser based filter rules do not apply:

<script src="https://unpkg.com/ua-parser-js@2/dist/ua-parser.min.js"></script>
<script src="https://unpkg.com/errorreporter@latest/dist/bundle/index.js"></script>

Example

This live example replaces the network request with a function that shows the reported message:

<div id="error-output"></div>

errorreporter.globalContext.fetch = (url, options) => {
    document.querySelector('#error-output').textContent =
        JSON.parse(options.body).errorMessage

    return Promise.resolve()
}
Promise.reject('Example error')

Receiving reports on the server

Each report is a "PUT" request with a JSON body to "/error_report" on the host the page was loaded from. Store or forward it as you like. The body contains:

  • "errorMessage", "stack", "url", "lineNumber" and "columnNumber": The error itself.
  • "absoluteURL": Address of the page where it happened.
  • "userAgent" and "technologyDescription": Raw user agent and a readable summary like "Firefox 140 (140.0 | Gecko 140.0) | Windows 10".
  • "issuesToIgnore": The filter rules active on the client.

Configuration

All settings are properties of the exported "errorHandler". Set them right after loading, before the first error occurs:

import {errorHandler} from 'errorreporter'

errorHandler.reportPath = '/api/client-error'
errorHandler.additionalIssuesToIgnore = [
    {errorMessage: /ResizeObserver loop/},
    {browser: {name: 'Safari', major: '15'}}
]
errorHandler.failedHandler = (error) => console.warn(error)
  • "reportPath": Path on the current host to send reports to. Defaults to "/error_report".
  • "additionalIssuesToIgnore": Your own filter rules, added to the built-in ones.
  • "issuesToIgnore": Replaces the built-in filter rules. They cover old Internet Explorer and Firefox versions and common messages caused by browser extensions or the environment.
  • "reportedHandler": Called with the response after a report was sent.
  • "failedHandler": Called if sending fails. Shows a browser alert by default.
  • "issueToIgnoreHandler": Called for filtered errors. If a rule without "errorMessage" matched, i.e. an unsupported browser, it shows an alert asking the visitor to upgrade by default.

Filter rules

A rule is a partial error description. It matches if all given properties match: strings have to be equal, regular expressions have to match. Available properties are "errorMessage", "technologyDescription", "ua" and the objects "browser" ("name", "major", "version"), "engine" and "os" ("name", "version").
